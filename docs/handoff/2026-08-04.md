## Decisions Made (Don't Revisit)

- **Duckle:** used as Python library (`pip install duckle>=0.5.9,<0.6`), NOT forked. Thin abstraction in `pipeline/runner.py`.
- **DuckLake catalog:** DuckDB file (zero dependencies). PostgreSQL abstraction added (`VWORLD_CATALOG_TYPE` env var) for future multi-user.
- **App split:** web console (React + FastAPI) for pipeline operations; existing Go/Wails desktop for full GIS. Web app only has minimal map preview (Leaflet or basic DeckGL).
- **One dataset = one DuckLake table:** schema evolves via snapshots. Province files appended via `write_mode="append"`.
- **Source modes:** dual-entry — crawl from VWorld URL OR load from local directory. Login screen offers both.
- **Credentials:** GUI login screen with env var fallback (VWORLD_URL, VWORLD_USERNAME, VWORLD_PASSWORD). Never persisted to disk.
- **Crawler:** paginated discovery (auto/manual), configurable download batch size (default 5), respectful crawling (browser UA, 1-3s delays, robots.txt).
- **Geometry rejects:** saved to `{dataset}_rejects` table with error reasons. Streamed in real-time via WebSocket.
- **WKB + bbox:** every row gets `geom_wkb`, `bbox_xmin/ymin/xmax/ymax` for Go/Wails consumption.
- **Post-crawl:** compact → reindex → spatial index (RTREE) after all provinces loaded.
