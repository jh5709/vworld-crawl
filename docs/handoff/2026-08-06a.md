## Completed Tickets

### ✅ #40 — 07 Incremental re-crawl + map preview

**What was built:**

**Incremental re-crawl (backend):**
- `POST /api/crawler/recrawl` — re-discovers all files, HEAD-checks previously-downloaded URLs (max 50, 0.2s pace) for per-file ETag/Last-Modified, compares against crawl_state via `check_changes()`
- `_detect_delta_date()` — extracts YYYY-MM-DD from filenames (YYYYMMDD / YYYY-MM-DD patterns)
- Delta dates attached to new+updated files for downstream pipeline use

**Delta pipeline support:**
- `PipelineRequest` + WS params extended: `data_date`, `write_mode` ("append"|"upsert"), `conflict_columns`
- Runner `_run_single_file` passes `mode=write_mode` + `conflictColumns` to `snk.ducklake`
- `code.sql` injects `data_date` as a literal DATE column when provided
- Schema Editor: "Advanced — delta load" collapsible section with checkbox, date picker, upsert-key column selector (populated from mapped columns)
- App.tsx → WS pipeline payload includes delta fields when enabled

**Map preview:**
- New `MapPreview.tsx` — deck.gl overlay with CARTO dark basemap tiles
- **Draw mode** toggle (box-select icon): disables map panning while active; drag rectangle to set spatial filter
- Auto row limits by geometry type (points 10k, lines 2k, polygons 500) — user draws rectangle to zoom into area of interest
- Layers: cyan ScatterplotLayer (points), fuschia GeoJsonLayer (lines), lime GeoJsonLayer (polygons)
- Full-table **bounding box** (dashed yellow) with "fit to table" button
- Side panel: **Statistics** tab (per-column counts, distinct, nulls, avg/quartiles; expandable rows with histograms — 15-bin numeric bars, render-as-bars categorical) and **Attributes** tab (paginated 50 rows/page with spatial filter)
- New backend endpoints: `GET /api/tables/{name}/bounds`, `GET /stats`, `POST /features`, `POST /attributes`, `POST /histogram`
- DuckLakeConsole: green **map-icon** per table row opens MapPreview overlay
- All pipeline tables auto-reprojected to EPSG:4326 (see CRS section below)

**CRS auto-reprojection:**
- Pipeline step 1.5: `detect_source_crs(read_path)` via `ST_CRS(geom)` (GDAL) or GeoParquet geo metadata
- When source CRS ≠ EPSG:4326: `code.sql` transform with `ST_Transform(geom, source, 'EPSG:4326', always_xy:=true)` — `always_xy` prevents PROJ's authority-compliant lat/lon axis swap
- Unknown CRS (missing .prj): warning log, pass-through unchanged
- Verified end-to-end: EPSG:3857 shapefile → stored as POINT(127, 37.5); 4326 GeoJSON → identical passthrough

### Bugs found during code review (fixed)

| Bug | Severity | Fix |
|-----|----------|-----|
| Recrawl would crash — `discover_all_pages` called with positional arg error, nonexistent `discover_page()`, and result treated as list of dicts (3 API misuse bugs in one call) | fatal | Rewrote to use correct `discover_all_pages(conn, url, state=op_state)` and `DiscoveryResult.files[index].url` attribute access pattern consistently |
| Recrawl compared listing-page ETag (irrelevant) against stored file ETag — every known file flagged false "updated" | fatal | Listing-page ETag assignment removed from `discover.py`; recrawl now HEAD-checks individual file URLs for real file ETag (max 50, 0.2s pacing) |
| Stats panel silently null: `quote_ident` returns `"col"`, but queries wrapped in `"{qc}"` → `""col""` → all per-column queries threw, fallback chain also threw, all 68 columns rendered null | critical | Rewritten as single `SUMMARIZE` pass (DUckDB) instead of N+1 per-column queries; now returns count/distinct/null/avg/median/quartiles + REAL data |
| Rect draw conflicted with map panning — every drag both panned and drew | high | Added explicit draw-mode toggle (box-select icon, cyan when active); `dragPan` disabled while drawing; drag events only process when drawMode is on |
| Delta upsert unreachable from UI — backend plumbing existed but no UI fields | high | Added SchemaEditor "Advanced — delta load" section (checkbox, date, key-column dropdown) wired through App.tsx → WS payload |
| `write_mode` no-l match / data_date not validated | low | `sparse` line cleaned up; `data_date` validated to YYYY-MM-DD format before SQL interpolation |
