## Phase 2 — Live testing findings (pending commit)

### Bug 6 — xf.project drops all columns when column_mapping is empty (NEW)

**Found while testing Bug 2b.** When `column_mapping: []` is sent, the runner
creates `keep_cols = ["geom"]` and calls `xf.project(columns=["geom"])`,
which drops every domain column (name, admin, scalerank, etc.). The table
ends up with only geometry-metadata columns (geom_wkb, bbox_*).

**Fix**: When `column_mapping` is empty, skip `xf.dropcol` and `xf.project`
entirely. All source columns pass through unchanged.

### Bug 2b — DuckLake schema evolution (RESEARCHED + FIXED)
- DuckLake does NOT auto-evolve on MERGE INTO (field-ID resolution is
  read-only; write path requires matching column counts)
- fix: ALTER TABLE ADD COLUMN pre-check in runner.py before upsert

**Details**: MERGE INTO (what duckle uses for upsert) requires matching column
counts between source and target. Our code.sql step injects ``data_date`` as
a literal DATE column, but the targDuring table (created without unc_mode)
won't have it. DuckLake's ALTER TABLE ADD COLUMN is supported without
rewriting data files (the field-ID resolution fills old rows with NULL).
